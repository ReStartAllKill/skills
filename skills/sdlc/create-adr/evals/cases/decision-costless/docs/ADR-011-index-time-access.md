# ADR-011 — 문서 열람 자격을 색인 시점에 판정해 색인에 넣는다

## 결정

문서가 검색 결과에 서려면 색인 시점에 판정한 허용 그룹이 질의자의 그룹과 겹쳐야 한다. 색인에는 문서 ID 와 허용 그룹 ID, 판정 시각만 넣고 사용자 목록은 넣지 않는다.

색인 쓰기 권한은 색인기 서비스 계정 하나에 둔다.

### Non-goals

- 그룹 멤버십을 누가 어떤 주기로 손보는지는 여기서 정하지 않는다. 디렉터리 서비스의 절차가 정본이다.
- 외부 공유 링크로 들어온 열람을 어떻게 다룰지는 별도 결정으로 남긴다.
- 색인에서 문서를 내리는 절차(보관·삭제 등)는 이 결정에 들어오지 않는다.

## 문맥과 결정 요인

사내 문서는 아무에게나 보이면 안 된다. 지금은 API 계층이 자격을 판정하고 검색 엔진은 걸린 문서를 그대로 돌려준다. API 를 거치지 않고 엔진을 직접 조회하면 판정이 통째로 우회된다.

**결정 요인** — 아래 대안의 공통 축이다.

- **우회 가능성:** 판정이 엔진 밖에 있으면 엔진 직접 조회로 넘어간다. 보안 감사에서 먼저 걸리는 축이다.
- **판정의 재현성:** 사후 감사에서 「그 시점에 이 사람이 이 문서를 볼 수 있었나」를 다시 세울 수 있어야 한다.
- **식별자 노출:** 색인 스냅샷은 보존 기간 동안 지워지지 않는다. 무엇을 넣는지가 되돌릴 수 없는 선택이다.

### ASM-001 — 보안 검토가 그룹 ID 의 색인 적재를 개인정보 처리로 보지 않는다

검토가 아직 진행 중이다. 그룹 ID 가 개인을 지목하지 않는다는 점을 근거로 삼았을 뿐, 확정된 판단을 받은 것은 아니다. 색인에 그룹 ID 를 싣는 부분이 이 전제 위에 서 있다.

## 대안

### ALT-001 — API 계층 판정 유지

지금 코드를 바꾸지 않아도 되고 권한 규칙을 바꿔도 재색인이 없다. 엔진 직접 조회로 우회된다.

### ALT-002 — 색인 시점 판정

엔진이 스스로 판정하므로 우회 경로가 없고, 판정 근거가 색인 시각과 함께 남는다. 권한 변경이 재색인이라 규칙이 결과에 반영될 때까지 시차가 생긴다.

### ALT-003 — 질의할 때마다 디렉터리에 묻는다

색인에 상시 상태를 두지 않아 남는 정보가 가장 적다. 질의마다 디렉터리를 호출해야 해서 디렉터리가 상시 가동돼야 한다.

**채택 근거:** 우회 가능성은 보안 쪽에서 되돌릴 수 없는 축이고, 나머지 둘은 운영으로 흡수된다.

## 결과

- 얻는 것: 엔진을 직접 조회해도 자격 없는 그룹에는 문서가 안 걸린다.
- 얻는 것: 어느 시점에 어느 그룹이 자격을 가졌는지가 색인 시각과 함께 남아 감사에서 그대로 재현된다.
- 얻는 것: API 가 멈춰도 열람 판정은 계속 선다.

## 확인과 재검토

- **확인:** `test_SearchRejectsUnauthorizedGroup` 이 정본이다. 허용 그룹에 없는 질의자에게 문서가 안 걸리는지를 이 테스트가 판정한다.

### RV-001 — ASM-001 이 깨진다

보안 검토가 그룹 ID 의 색인 적재를 개인정보 처리로 판단하면 이 결정을 다시 연다. 이미 쌓인 스냅샷은 회수할 수 없으므로 그때는 색인 구성부터 다시 정한다.

- **링크:** `src/access/acl_index.ts` 가 색인에 넣는 값의 정본이다.
